# Часть 1. Классная работа

### Шаг 1. Зачем нужна нить и почему без неё «не живёт» чат

**Что делаем.** Разбираемся с проблемой занятия 7 и способом её решения.

**Как это работает.** Программа на Python выполняет команды **по очереди**. Если она стоит на `input("> ")`, никакой другой код не выполняется, пока пользователь не нажмёт Enter. Именно поэтому внешние сообщения «застревали».

Решение — **нить** (thread): это отдельная «дорога» внутри программы, по которой код может бежать параллельно. Мы запустим в нити функцию, которая в цикле спрашивает `poll` и печатает новые сообщения, а главная нить продолжит ждать ввод от пользователя.

### Шаг 2. Функция listen: крутится в фоне

**Что делаем.** Пишем функцию `listen(username, last)` — «слушателя» новых сообщений.

**Как это работает.** Внутри — бесконечный цикл: спросили `poll`, напечатали всё новое, обновили `last`, ненадолго заснули (`time.sleep`), затем снова. Пауза важна: без неё программа заваливала бы сервер запросами.

**Пишем.** После `main` (или перед ней — порядок не критичен, но образец хранит её отдельно) набираем:

```python
def listen(username, last):
    while True:
        messages = poll(last)
        for message in messages:
            print(message_str(message))
            last = message.get("id", last)
        time.sleep(0.5)
```

**Как это работает.**

1. `while True` — слушатель работает, пока программа не закончится.
2. `poll(last)` — каждые полсекунды спрашиваем, что нового.
3. `message_str(message)` — печатаем красиво, как на занятии 6.
4. `last = message.get("id", last)` — двигаем точку отсчёта.
5. `time.sleep(0.5)` — «спим» полсекунды, чтобы не спамить сервер.

**Проверь себя.** Запустите `python chat.py` — функция определилась, но её надо будет запустить в нити (шаг 3).

### Шаг 3. Запускаем нить в main

**Что делаем.** Подключаем «слушателя» к главной функции.

**Как это работает.** Вместо проверки сообщений в начале каждой итерации цикла `main` мы один раз запускаем нить. После этого `main` занимается только вводом, а печать чужих сообщений — дело нити.

**Пишем.** В функции `main` заменяем блок проверки сообщений (строки c `messages = poll(last)` до обновления `last`) на запуск нити:

```python
def main():
    username, last = join()
    if username is None:
        return
    t = threading.Thread(target=listen, args=(username, last))
    t.start()
    while True:
        text = input("> ")
        if not text:
            continue
        if text == "exit":
            break
        send(username, text)
```

**Как это работает.**

1. `threading.Thread(target=listen, args=(username, last))` — создаём нить, которая выполнит функцию `listen` с нашими `username` и `last`.
2. `t.start()` — запускаем нить: теперь `listen` крутится в фоне.
3. Цикл ввода стал короче: только `input`, проверка пустой строки, `exit` и `send`.
4. Нить и главная нить живут одновременно: мы печатаем, а чужие сообщения появляются сами.

### Шаг 4. Запуск программы: `if __name__ == "__main__":`

**Что делаем.** Добавляем точку входа, чтобы `python chat.py` запускал чат.

**Как это работает.** Когда Python выполняет файл, он кладёт в переменную `__name__` значение `"__main__"`. Проверка `if __name__ == "__main__":` означает: «этот код выполнится только если файл запущен напрямую». Если `chat.py` импортируют как модуль (так мы делали в проверках `python -c "import chat; ..."`), точка входа не сработает — и это правильно.

**Пишем.** В самом конце файла (после всех функций) набираем:

```python
if __name__ == "__main__":
    main()
```

**Проверь себя.** Запустите `python chat.py` (в папке `Мой чат`) — чат должен начать работать: приветствие, курсор `>`, выход по `exit`.
