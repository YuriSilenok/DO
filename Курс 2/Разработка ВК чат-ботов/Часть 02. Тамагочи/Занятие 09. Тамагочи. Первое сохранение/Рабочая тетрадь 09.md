## Рабочее место и порядок действий

Откройте **VS Code → File → Open Folder / Файл → Открыть папку → vk_bot**. Слева в **Explorer** (`Ctrl+Shift+E`) открывайте и создавайте файлы; код вставляйте в центральную вкладку `.py`. Файлы проекта находятся рядом с `.venv`, а не внутри неё. Сохраняйте через `Ctrl+S`.

Команды вводятся внизу, **Terminal → New Terminal / Терминал → Создать терминал**, профиль **PowerShell**. Введите `Get-Location` и нажмите Enter: должна быть открыта папка `vk_bot`. Если путь другой, откройте нужную папку и создайте новый терминал. `PS …>` — приглашение оболочки, его копировать не нужно; `>>>` — интерактивный Python, выйдите из него через `exit()` и Enter. Не используйте для запуска панели Output или Debug Console.

Используем окружение занятий 02–04. Если его нет: в TERMINAL выполните `py -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install vk_api`. `sqlite3`, `pathlib` и `time` входят в стандартную библиотеку, отдельно через pip их не устанавливают.

Копируйте **один блок до 10 строк за раз**. Перед блоком указано точное место, причина и замена. Сохраняйте начальные пробелы; если VS Code добавил лишний отступ, выделите вставленные строки и уменьшите его через Shift+Tab. Не добавляйте блок повторно, если уже сделали действие по описанию. Если функция собирается несколькими блоками, запустите проверку только после указанного завершения.

Вопросы и игровые команды отправляйте **в личном диалоге сообщества VK**, а не в PowerShell. В TERMINAL вводятся только команды запуска и секрет после приглашения `Токен сообщества:`. Символы getpass не отображаются. Перед правкой работающего бота нажмите `Ctrl+C` в его терминале, дождитесь `PS`, сохраните файл и запустите заново. Новые изменения не подхватываются работающей программой автоматически.

Ошибки читайте в TERMINAL: последняя строка содержит тип и описание, выше указаны файл и номер строки. Копию полного исходника в тетради не ищем: собираем проект по этапам и проверяем каждую часть.

### Шаг 2. Открываем файл БД

**Где работаем:** VS Code → новый pet_db.py в корне vk_bot.

В этом модуле будут только функции хранения. Файл pet_bot.py позже будет отвечать за VK. Начните open_db двумя блоками этого и следующего шага: до конца шага 3 функцию не проверяйте.

**Куда вставить:** В пустой pet_db.py.

**Зачем и почему здесь:** Импорты доступны всему модулю; time понадобится для сохранения момента создания.

```python
import sqlite3
import time
from pathlib import Path
```

**Куда вставить:** После импортов, без внешнего отступа.

**Зачем и почему здесь:** Путь задаётся относительно самого файла: база не потеряется при запуске из другой папки. Row позволяет читать поля по названиям вместо индексов.

```python
def open_db():
    path = Path(__file__).resolve().with_name("tamagotchi.db")
    conn = sqlite3.connect(path)
    conn.row_factory = sqlite3.Row
    cur = conn.cursor()
```

**Что наблюдать и как проверить:** В pet_db.py одна функция open_db. Пока она только открывает соединение: продолжение и возврат результата добавляются ниже.

### Шаг 3. Создаём таблицу

**Где работаем:** Редактор pet_db.py, продолжение open_db.

Схема сразу содержит updated_at — целое число секунд с начала эпохи. Пока это время создания, позже используем для расчёта потребностей. IF NOT EXISTS не изменяет старую схему, поэтому проект использует отдельное имя tamagotchi.db.

**Куда вставить:** После cur = conn.cursor(), внутри open_db. Каждая строка тела имеет 4 пробела.

**Зачем и почему здесь:** Таблица готовится перед возвратом conn; дальнейшие функции не смогут вставлять строки в несуществующую таблицу.

```python
    cur.execute("""CREATE TABLE IF NOT EXISTS pets (
        owner_id INTEGER PRIMARY KEY, name TEXT NOT NULL,
        satiety INTEGER NOT NULL DEFAULT 70,
        mood INTEGER NOT NULL DEFAULT 70,
        energy INTEGER NOT NULL DEFAULT 70,
        updated_at INTEGER NOT NULL
    )""")
    conn.commit()
    return conn
```

**Что наблюдать и как проверить:** Функция завершена return conn. Для пробного запуска создайте db_check.py: следующими блоками откроем БД и проверим её через SELECT, а не просмотр бинарного файла.

### Шаг 4. Читаем профиль

**Где работаем:** Редактор pet_db.py после open_db.

Добавьте функцию чтения. Def размещается без внешнего отступа; тело — с четырьмя пробелами. Функции не вызываются сами от одного появления в файле.

**Куда вставить:** После return conn функции open_db, с новой строки без отступа.

**Зачем и почему здесь:** Один запрос читает только владельца по параметру. Кортеж из одного значения требует запятой; None означает отсутствие питомца.

```python
def get_pet(conn, owner_id):
    cur = conn.cursor()
    cur.execute("SELECT * FROM pets WHERE owner_id = ?", (owner_id,))
    return cur.fetchone()
```

**Куда вставить:** В новый файл db_check.py. Не вставляйте в pet_db.py.

**Зачем и почему здесь:** Отдельный проверочный файл вызывает функции модуля; finally закрывает соединение даже при ошибке.

```python
from pet_db import open_db, get_pet

conn = open_db()
try:
    print(get_pet(conn, 1))
finally:
    conn.close()
```

**Куда вставить:** В TERMINAL VS Code, после сохранения обоих файлов.

**Зачем и почему здесь:** Python запускает проверку, а импорт загружает функции из соседнего pet_db.py.

```powershell

```

**Что наблюдать и как проверить:** В TERMINAL напечатано None, затем вернулось PS. В Explorer появился tamagotchi.db. Он бинарный, открывать как текст и менять его в редакторе не нужно.

### Шаг 5. Приютили одного питомца

**Где работаем:** Редактор pet_db.py и db_check.py.

Добавьте создание строки с параметрами. OR IGNORE не заменяет существующего питомца при повторном ID. Настоящий ID VK подставит бот на следующем занятии; сейчас учебный владелец — 1.

**Куда вставить:** В конец pet_db.py после get_pet.

**Зачем и почему здесь:** Показатели возьмутся из DEFAULT, время — с часов компьютера. Commit фиксирует вставку; rowcount сообщает, создана ли новая строка.

```python
def adopt_pet(conn, owner_id):
    cur = conn.cursor()
    cur.execute(
        "INSERT OR IGNORE INTO pets (owner_id, name, updated_at) VALUES (?, ?, ?)",
        (owner_id, "Искра", int(time.time()))
    )
    created = cur.rowcount
    conn.commit()
    return created
```

**Куда вставить:** В db_check.py замените строку импорта первой строкой этого блока.

**Зачем и почему здесь:** Функцию нужно импортировать до её вызова в проверочном файле.

```python
from pet_db import open_db, get_pet, adopt_pet
```

**Куда вставить:** В db_check.py замените прежний print(get_pet(conn, 1)) внутри try. Начальный отступ — 4 пробела.

**Зачем и почему здесь:** Сначала записываем, затем перечитываем: так видим именно сохранённое значение, а не переменную из памяти.

```python
    print("Создан:", adopt_pet(conn, 1))
    pet = get_pet(conn, 1)
    print(pet["name"], pet["satiety"], pet["mood"], pet["energy"])
```

**Что наблюдать и как проверить:** Сохраните Ctrl+S и запустите db_check.py дважды. Первый раз «Создан: 1», второй — «Создан: 0»; оба раза Искра 70 70 70. Значит повторный запуск не создаёт дубль и данные сохранены.
