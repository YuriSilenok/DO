## Классная работа

### Шаг 1. Определяем ход времени

**Где работаем:** VS Code → pet_rules.md и pet_db.py.

За каждые полные 10 минут: −5 сытости, −3 настроения, −2 энергии. Считаем прошедшие периоды при следующем сообщении владельца — это отложенный пересчёт. Пока бот выключен, SQL не выполняется, но прошедшее время учитывается после запуска. Фоновые потоки и time.sleep в слушатель не добавляем: они усложнят код или заблокируют ответы.

**Куда вставить:** В pet_db.py сразу после импортов, перед open_db.

**Зачем и почему здесь:** Общая константа используется всеми пересчётами. 600 секунд — 10 минут; при тестах временно заменим на 2.

```python
TICK_SECONDS = 600
```

**Что наблюдать и как проверить:** В правилах записаны скорость и нижняя граница 0. Питомец не исчезает при 0: кормление и отдых возвращают возможность играть.

### Шаг 2. Считаем полные периоды

**Где работаем:** Редактор pet_db.py после функций ухода.

Refresh_pet строим двумя блоками этого и следующего шага. До их завершения не запускайте бота. Параметр now можно передать при проверке; обычный бот берёт time.time. Это абсолютные секунды, которые можно сравнивать между запусками; не сохраняем время работы процесса.

**Куда вставить:** В конец pet_db.py, без внешнего отступа.

**Зачем и почему здесь:** Сначала читаем владельца. Отсутствующего питомца не создаём, отрицательный ход часов не должен увеличивать показатели.

```python
def refresh_pet(conn, owner_id, now=None):
    pet = get_pet(conn, owner_id)
    if pet is None:
        return None
    now = int(time.time()) if now is None else int(now)
    ticks = max(0, (now - pet["updated_at"]) // TICK_SECONDS)
    if ticks == 0:
        return pet
```

**Что наблюдать и как проверить:** Формула при 599 секундах даёт 0 периодов, при 600 — 1. Проверку функции выполняем после завершения шага 3.

- [ ] Получилось; могу объяснить место и назначение правки.

### Шаг 3. Сохраняем прошедшее время

**Где работаем:** Редактор pet_db.py: продолжение refresh_pet.

Снижение и отметку обработанного времени сохраняем одним UPDATE. Время передвигаем на число полных периодов, а не на now: остаток секунд не должен теряться при частых сообщениях.

**Куда вставить:** После проверки ticks == 0, внутри refresh_pet. With имеет 4 пробела.

**Зачем и почему здесь:** MAX сохраняет нижнюю границу 0; updated_at увеличивается вместе с потребностями, чтобы повторный запрос не списал тот же период.

```python
    with conn:
        conn.execute(
            "UPDATE pets SET satiety = MAX(0, satiety - ?), "
            "mood = MAX(0, mood - ?), energy = MAX(0, energy - ?), "
            "updated_at = updated_at + ? WHERE owner_id = ?",
            (5 * ticks, 3 * ticks, 2 * ticks, ticks * TICK_SECONDS, owner_id)
        )
    return get_pet(conn, owner_id)
```

**Что наблюдать и как проверить:** Функция завершена возвратом перечитанной строки. В ней один UPDATE, без sleep и без самостоятельного цикла ожидания.

- [ ] Получилось; могу объяснить место и назначение правки.
