## Рабочее место и порядок действий

Откройте **VS Code → File → Open Folder / Файл → Открыть папку → vk_bot**. Слева в **Explorer** (`Ctrl+Shift+E`) открывайте и создавайте файлы; код вставляйте в центральную вкладку `.py`. Файлы проекта находятся рядом с `.venv`, а не внутри неё. Сохраняйте через `Ctrl+S`.

Команды вводятся внизу, **Terminal → New Terminal / Терминал → Создать терминал**, профиль **PowerShell**. Введите `Get-Location` и нажмите Enter: должна быть открыта папка `vk_bot`. Если путь другой, откройте нужную папку и создайте новый терминал. `PS …>` — приглашение оболочки, его копировать не нужно; `>>>` — интерактивный Python, выйдите из него через `exit()` и Enter. Не используйте для запуска панели Output или Debug Console.

Используем окружение занятий 02–04. Если его нет: в TERMINAL выполните `py -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install vk_api`. `sqlite3`, `pathlib` и `time` входят в стандартную библиотеку, отдельно через pip их не устанавливают.

Копируйте **один блок до 10 строк за раз**. Перед блоком указано точное место, причина и замена. Сохраняйте начальные пробелы; если VS Code добавил лишний отступ, выделите вставленные строки и уменьшите его через Shift+Tab. Не добавляйте блок повторно, если уже сделали действие по описанию. Если функция собирается несколькими блоками, запустите проверку только после указанного завершения.

Вопросы и игровые команды отправляйте **в личном диалоге сообщества VK**, а не в PowerShell. В TERMINAL вводятся только команды запуска и секрет после приглашения `Токен сообщества:`. Символы getpass не отображаются. Перед правкой работающего бота нажмите `Ctrl+C` в его терминале, дождитесь `PS`, сохраните файл и запустите заново. Новые изменения не подхватываются работающей программой автоматически.

Ошибки читайте в TERMINAL: последняя строка содержит тип и описание, выше указаны файл и номер строки. Копию полного исходника в тетради не ищем: собираем проект по этапам и проверяем каждую часть.

Правой кнопкой по bot.py → Copy, затем Paste в папке проекта; переименуйте копию F2 в pet_bot.py. Оригинал сохраните. В копии удалите import random и список answers. Получение ключа, подключение VK, фильтр личных сообщений и единственный вызов messages.send сохраняем.

### Шаг 2. Подключаем хранилище

**Где работаем:** Редактор pet_bot.py: импорты, затем область перед циклом.

Остановите копию. Добавьте импорт функций и одно соединение. Pet_db.py должен лежать рядом: ModuleNotFoundError обычно означает неправильное имя файла или папку.

**Куда вставить:** К импортам вверху pet_bot.py, до token.

**Зачем и почему здесь:** Модуль определяет функции, но не запускает свой отдельный цикл или консольный ввод.

```python
from pet_db import open_db, get_pet, adopt_pet
```

**Куда вставить:** После создания keyboard, непосредственно перед for event.

**Зачем и почему здесь:** Соединение нужно открыть до обработки любого сообщения и держать до завершения слушателя.

```python
conn = open_db()
```

**Куда вставить:** После conn = open_db(), перед for event. Затем выделите весь существующий цикл вместе с отправкой и сдвиньте Tab на 4 пробела. До добавления finally файл не запускайте.

**Зачем и почему здесь:** Try охватывает весь слушатель, а не отдельную ветку. Теперь for имеет 4 пробела, if MESSAGE_NEW — 8, основная цепочка команд — 12.

```python
try:
```

**Куда вставить:** После всего сдвинутого цикла, в конце pet_bot.py, без отступа перед finally.

**Зачем и почему здесь:** База закрывается при завершении, включая Ctrl+C; внутри цикла она должна оставаться открытой.

```python
finally:
    conn.close()
```

**Что наблюдать и как проверить:** Сохраните и запустите бота заново: после «Помощь» он отвечает; Ctrl+C возвращает PS. Нет ProgrammingError о закрытой БД.

### Шаг 3. Создаём питомца владельца

**Где работаем:** Редактор pet_bot.py: цепочка команд внутри MESSAGE_NEW.

Вставляйте elif на уровне остальных веток — с 12 пробелами. User_id уже взят из события: не подменяйте его учебным числом 1.

**Куда вставить:** Перед последним else общей цепочки, не после него.

**Зачем и почему здесь:** Команда проверяется раньше запасной подсказки; функция защищает от повторной вставки.


**Что наблюдать и как проверить:** После перезапуска дважды отправьте «Приютить»: создание, затем отказ повтора. Искра не сбрасывается на повторной команде.

### Шаг 4. Показываем карточку

**Где работаем:** Редактор pet_bot.py: рядом с новой веткой.

Читаем именованные поля sqlite3.Row. Если строки нет, к её полям обращаться нельзя.

**Зачем и почему здесь:** Чтение происходит по владельцу текущего сообщения, а None обрабатывается до форматирования.

**Что наблюдать и как проверить:** Перезапустите. «Питомец» показывает Искру 70/70/70. С другого аккаунта до создания — приглашение приютить. Вызов отправки по-прежнему один.
