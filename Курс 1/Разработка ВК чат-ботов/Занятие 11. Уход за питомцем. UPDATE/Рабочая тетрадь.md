## Как выполнять действия в VS Code

1. Откройте **File → Open Folder / Файл → Открыть папку** и выберите свою папку `vk_bot`. Слева в **Explorer / Проводник** (`Ctrl+Shift+E`) находятся файлы, в центре — редактор выбранного файла. Файлы `.py` создавайте в корне `vk_bot`, не внутри `.venv`.
2. Код Python вводите в центральный редактор файла `.py`, затем нажимайте `Ctrl+S`. Точка на вкладке означает несохранённые изменения. Фрагменты SQL помещайте в кавычках в аргументы `execute` в Python-файле; их не вводят как команды PowerShell.
3. Команды установки и запуска вводите внизу: **Terminal → New Terminal / Терминал → Создать терминал**. В этой тетради для Windows используется **PowerShell**. Щёлкните после приглашения `PS …>`, наберите команду без самого приглашения и нажмите `Enter`. Панели **Output / Вывод** и **Debug Console / Консоль отладки** для этих команд не подходят.
4. Проверьте текущую папку командой `Get-Location`: путь должен оканчиваться на `vk_bot`. Командой `Get-ChildItem` посмотрите файлы: нужный `.py` и папка `.venv` должны быть здесь. Если папка другая, откройте правильную через File → Open Folder и создайте новый терминал. Если видите `>>>`, открыт интерактивный Python: введите `exit()` и Enter, чтобы вернуться к PowerShell.
5. После создания окружения запускайте нужный файл командой из блока ниже. Начальное `.\` означает «из текущей папки». Если PowerShell активировал среду автоматически, прямой путь всё равно подходит. Если `.venv` ещё нет, сначала выполните создание среды из занятия 2.

```powershell
.\.venv\Scripts\python.exe pet_bot.py
```

6. Пока бот работает, приглашение `PS …>` не возвращается: терминал занят программой. Вопросы и команды боту отправляйте в **диалоге с сообществом VK**. Консольной программе ответ на `input` вводите в том же TERMINAL после её вопроса. Ключ вводится только после приглашения `Токен сообщества:`; символы `getpass` не отображаются.
7. Перед новой правкой щёлкните в TERMINAL и нажмите `Ctrl+C`, дождитесь приглашения PowerShell. Исправьте файл, сохраните `Ctrl+S`, снова выполните команду запуска. Работающая программа не подхватывает сохранённые изменения сама. Ошибки Python читаем в TERMINAL: последняя строка — тип и описание, выше — файл и номер строки. Кнопка Problems / Проблемы помогает найти синтаксические замечания, но не заменяет запуск.

**Как проверять SQLite:** `pets.db` не открывают как текст и не запускают Python. Состояние проверяется запросами SELECT: в занятии 9 результат печатается в TERMINAL, с занятия 10 — показывается командами «Питомец» и «Инвентарь» в VK. Сначала сохраните программу, затем запустите её; одно появление файла БД не доказывает правильность записей.

## Как копировать учебные блоки

Копируйте **по одному блоку до 10 строк**, а не весь материал занятия. Перед каждым блоком указаны файл, место вставки или замены и причина такого расположения. Несколько блоков одного шага выполняйте по порядку. Если код уже набран по описанию, второй раз его не добавляйте — сравните с образцом.

Сохраняйте начальные пробелы: они показывают вложенность Python. После вставки проверьте выравнивание с названными соседними строками; VS Code может автоматически добавить лишний отступ. Код с меткой `python` идёт в редактор `.py`, `powershell` — в TERMINAL Windows, `bash` — в Termux. Номер шага, пояснение и ограждения из трёх обратных кавычек в файл не переносятся. В блоках нет скрытого продолжения в виде троеточия: если блок открывает try или функцию, явно указано, каким следующим блоком завершить сборку до запуска.

### Шаг 2. Пишем UPDATE

**Где работаем:** Редактор pet_bot.py: новая feed_pet рядом с get_pet, до основного кода.

**Действие:** Добавьте функцию feed_pet(conn, owner_id) до подключения. Внутри создайте курсор. Составьте запрос UPDATE pets SET satiety = MIN(100, satiety + 20) WHERE owner_id = ? AND satiety < 100. Выполните с параметром owner_id, затем commit. Верните cur.rowcount. WHERE обязателен: без него поменяются все питомцы. MIN здесь сравнивает два числа в SQLite.

**Порядок выполнения и ориентиры:** Объявите функцию на нулевом отступе. Внутри последовательно расположите создание курсора, execute, commit, return rowcount. Запрос UPDATE — строковый аргумент execute, ID — второй аргумент. Не вводите UPDATE в PowerShell.

**Блок 2.1 · куда вставить:** Новая функция после get_pet, перед token. Не помещайте def в цикл событий.

**Зачем и почему здесь:** БД меняется внутри отдельного действия, а rowcount сообщает, подошла ли строка условиям.

```python
def feed_pet(conn, owner_id):
    cur = conn.cursor()
    cur.execute(
        "UPDATE pets SET satiety = MIN(100, satiety + 20) "
        "WHERE owner_id = ? AND satiety < 100", (owner_id,)
    )
    changed = cur.rowcount
    conn.commit()
    return changed
```

**Что должно получиться:** После сохранения и перезапуска нет SyntaxError. Реальное изменение проверяется вызовом команды на следующем шаге, а не появлением функции в файле.

**Проверка:** изменяется только строка владельца; функция возвращает 1 при изменении или 0, если подходящей строки нет.

- [ ] Получилось; могу объяснить изменение.
