После каждого шага сохраняйте файл и выполняйте проверку.

## Классная работа

### Шаг 1. Готовим файл и библиотеку

Сохраните консольный черновик и создайте `bot.py`. Из терминала проекта выполните `.venv\Scripts\python.exe -m pip install vk_api`. Затем проверьте импорт командой `.venv\Scripts\python.exe -c "import vk_api; print('OK')"`. Сообщение Requirement already satisfied также означает, что пакет установлен.

**Проверка:** импорт выводит OK без ошибки.

- [ ] Получилось; могу объяснить изменение.

### Шаг 2. Отделяем секрет

В начале bot.py подключите `getpass` из модуля getpass. Получите токен через вызов `getpass("Токен сообщества: ")`, сохраните его в `token`. При запуске ввод скрыт; это не зависание. Создайте `group_id` с положительным числовым ID. Настоящий токен в файле не записываем.

**Проверка:** в файле есть запрос токена, но нет самого ключа.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Создаём подключение

Рядом с импортами подключите `vk_api`, а из `vk_api.bot_longpoll` — `VkBotLongPoll` и `VkBotEventType`. После ID создайте `vk` вызовом `vk_api.VkApi(token=token)`. Затем создайте `longpoll` выражением `VkBotLongPoll(vk, group_id)`. Пока используем версию API библиотеки; если в учебном сообществе настроена другая, преподаватель согласует `api_version` и настройки VK. После создания longpoll выведите «Бот запущен». Запустите файл через Python окружения.

**Проверка:** подключение проходит; если 5 — проверьте ключ, если 15 — права и настройки сообщества. Сам токен не показывайте.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Слушаем личный диалог

После подключения создайте цикл `for event in longpoll.listen():`. Внутри обрабатывайте только `event.type == VkBotEventType.MESSAGE_NEW`. Возьмите `message = event.message`. Пропустите событие через `continue`, если `message.peer_id != message.from_id` или `message.from_id <= 0`: беседы пока не поддерживаем. Оставшиеся строки находятся внутри цикла и проверки MESSAGE_NEW. Сохраните `message.from_id` в `user_id`, а `message.text.strip().lower()` — в `user_text`. Временно печатайте только «Получено сообщение», без чужого текста.

**Проверка:** личное сообщение вызывает отметку в терминале. Беседы не обрабатываются.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Переносим предсказания

Перенесите из magic_ball.py импорт random и список answers. Импорт — наверх, список — перед циклом, без input и консольного вывода. Внутри обработки сообщения получите `reply = random.choice(answers)`.

**Проверка:** подготовка выполняется один раз, выбор — на каждое сообщение.

- [ ] Получилось; могу объяснить изменение.

### Шаг 6. Отправляем ответ

После выбора reply вызовите `vk.method` с именем метода `"messages.send"` и словарём параметров. В словаре укажите `peer_id` со значением `message.peer_id`, `message` со значением `reply`, `random_id` со значением `vk_api.utils.get_random_id()`. Функция создаёт случайный идентификатор отправки. Не оставляйте старый тестовый вызов отправки рядом: ответ должен отправляться один раз.

**Проверка:** одно личное сообщение даёт один ответ. Для остановки нажмите Ctrl+C.

- [ ] Получилось; могу объяснить изменение.

### Шаг 7. Проверяем запуск заново

Остановите процесс, сохраните файл и запустите заново. Снова введите токен в скрытом приглашении. Напишите три вопроса. Если бот молчит, проверьте message_new, ID, права ключа, запущенный процесс и выбранное окружение.

**Проверка:** бот отвечает после повторного запуска; ключ не оказался в исходнике.

- [ ] Получилось; могу объяснить изменение.

## Домашняя работа · небольшая доработка

Измените формирование reply: перед выбранным предсказанием добавляйте короткую фразу «Шар думает…». Используйте соединение строк или f-строку. Список предсказаний оставьте прежним. Убедитесь, что бот отправляет одну строку ответа одним сообщением.
