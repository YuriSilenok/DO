## Как выполнять действия в VS Code

1. Откройте **File → Open Folder / Файл → Открыть папку** и выберите свою папку `vk_bot`. Слева в **Explorer / Проводник** (`Ctrl+Shift+E`) находятся файлы, в центре — редактор выбранного файла. Файлы `.py` создавайте в корне `vk_bot`, не внутри `.venv`.
2. Код Python вводите в центральный редактор файла `.py`, затем нажимайте `Ctrl+S`. Точка на вкладке означает несохранённые изменения. Фрагменты SQL помещайте в кавычках в аргументы `execute` в Python-файле; их не вводят как команды PowerShell.
3. Команды установки и запуска вводите внизу: **Terminal → New Terminal / Терминал → Создать терминал**. В этой тетради для Windows используется **PowerShell**. Щёлкните после приглашения `PS …>`, наберите команду без самого приглашения и нажмите `Enter`. Панели **Output / Вывод** и **Debug Console / Консоль отладки** для этих команд не подходят.
4. Проверьте текущую папку командой `Get-Location`: путь должен оканчиваться на `vk_bot`. Командой `Get-ChildItem` посмотрите файлы: нужный `.py` и папка `.venv` должны быть здесь. Если папка другая, откройте правильную через File → Open Folder и создайте новый терминал. Если видите `>>>`, открыт интерактивный Python: введите `exit()` и Enter, чтобы вернуться к PowerShell.
5. После создания окружения запускайте нужный файл командой из блока ниже. Начальное `.\` означает «из текущей папки». Если PowerShell активировал среду автоматически, прямой путь всё равно подходит. Если `.venv` ещё нет, сначала выполните создание среды из занятия 2.

```powershell
.\.venv\Scripts\python.exe bot.py
```

6. Пока бот работает, приглашение `PS …>` не возвращается: терминал занят программой. Вопросы и команды боту отправляйте в **диалоге с сообществом VK**. Консольной программе ответ на `input` вводите в том же TERMINAL после её вопроса. Ключ вводится только после приглашения `Токен сообщества:`; символы `getpass` не отображаются.
7. Перед новой правкой щёлкните в TERMINAL и нажмите `Ctrl+C`, дождитесь приглашения PowerShell. Исправьте файл, сохраните `Ctrl+S`, снова выполните команду запуска. Работающая программа не подхватывает сохранённые изменения сама. Ошибки Python читаем в TERMINAL: последняя строка — тип и описание, выше — файл и номер строки. Кнопка Problems / Проблемы помогает найти синтаксические замечания, но не заменяет запуск.

**Исключение этого занятия:** подготовка файла проходит в VS Code, команды `pkg`, `source`, `termux-*` и запуск на телефоне — только в приложении Termux. Команду Windows из примера используйте лишь при запуске на ПК.

## Как копировать учебные блоки

Копируйте **по одному блоку до 10 строк**, а не весь материал занятия. Перед каждым блоком указаны файл, место вставки или замены и причина такого расположения. Несколько блоков одного шага выполняйте по порядку. Если код уже набран по описанию, второй раз его не добавляйте — сравните с образцом.

Сохраняйте начальные пробелы: они показывают вложенность Python. После вставки проверьте выравнивание с названными соседними строками; VS Code может автоматически добавить лишний отступ. Код с меткой `python` идёт в редактор `.py`, `powershell` — в TERMINAL Windows, `bash` — в Termux. Номер шага, пояснение и ограждения из трёх обратных кавычек в файл не переносятся. В блоках нет скрытого продолжения в виде троеточия: если блок открывает try или функцию, явно указано, каким следующим блоком завершить сборку до запуска.

## Классная работа

### Шаг 1. Сначала устанавливаем Termux

**Где работаем:** Телефон Android: браузер и установка приложения, не TERMINAL VS Code.

**Действие:** Выберите [F-Droid](https://f-droid.org/packages/com.termux/) или [официальные релизы](https://github.com/termux/termux-app/releases), учитывая требования конкретной сборки к Android. Установите приложение. Приложение и плагины берите из одного источника: подписи разных сборок несовместимы.

**Порядок выполнения и ориентиры:** На компьютере оставьте VS Code с вашим bot.py. На телефоне откройте выбранную официальную страницу Termux, установите приложение и запустите его.

**Что должно получиться:** Видно текстовое окно Termux с приглашением ввода. До его появления команды pkg вводить негде.

**Проверка:** Termux открывается и показывает приглашение терминала.

- [ ] Получилось; могу объяснить изменение.

### Шаг 2. Готовим Python

**Где работаем:** Только приложение Termux на телефоне.

**Действие:** По очереди выполните `pkg update`, `pkg upgrade`, затем `pkg install python nano termux-tools`. Прочитайте запросы подтверждения. Проверьте `python --version`. Не обновляйте системный pip командой pip install --upgrade pip.

**Порядок выполнения и ориентиры:** Вводите каждую команду pkg отдельной строкой и нажимайте Enter. Дождитесь завершения одной команды, затем вводите следующую; на запрос продолжения прочитайте подсказку и подтвердите. Команды pkg не вводите в Windows PowerShell.

**Блок 2.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Сначала обновляем пакеты, затем ставим Python и проверяем его доступность.

```bash
pkg update
pkg upgrade
pkg install python nano termux-tools
python --version
```

**Что должно получиться:** После python --version в Termux видна версия Python 3. Если pkg не найден, проверьте, что вы действительно в Termux.

**Проверка:** Python 3 запускается без ошибок.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Ориентируемся в папках

**Где работаем:** Termux: строка ввода после приглашения.

**Действие:** Выполните `pwd`, `ls`. Создайте каталог `mkdir -p ~/bot`, перейдите `cd ~/bot`. Символ ~ означает домашнюю папку. Здесь храним рабочие файлы, а не в общем хранилище телефона.

**Порядок выполнения и ориентиры:** Введите pwd и Enter, затем ls и Enter. После mkdir и cd снова выполните pwd. Команда cd сама обычно ничего не печатает.

**Блок 3.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Каталог нужно создать до перехода; последний pwd подтверждает место работы.

```bash
pwd
ls
mkdir -p ~/bot
cd ~/bot
pwd
```

**Что должно получиться:** Новый pwd заканчивается на /home/bot. Это подтверждает переход, даже если cd не вывела сообщения.

**Проверка:** pwd заканчивается на /home/bot.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Переносим свой файл

**Где работаем:** VS Code на ПК → файл bot.py; затем файловый менеджер телефона и Termux.

**Действие:** Скопируйте уже написанный вами bot.py без секрета на телефон как файл, например по USB. Сохраните его в «Загрузки». Выполните `termux-setup-storage` и разрешите доступ, затем `cp ~/storage/downloads/bot.py ~/bot/`. Это перенос собственного результата, а не готового решения из тетради. Токен переносить вместе с файлом не нужно.

**Порядок выполнения и ориентиры:** В VS Code сохраните файл Ctrl+S. Передайте именно файл bot.py, не папку .venv. На телефоне найдите его в «Загрузках». В Termux последовательно выполните разрешение доступа и копирование из задания.

**Блок 4.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Разрешение доступа требуется до копирования; ls проверяет, что файл оказался в рабочем каталоге.

```bash
termux-setup-storage
cp ~/storage/downloads/bot.py ~/bot/
ls ~/bot
```

**Что должно получиться:** В Termux выполните ls ~/bot: видно bot.py. Если cp пишет No such file, проверьте имя загруженного файла и папку downloads.

**Проверка:** ls в ~/bot показывает bot.py; getpass остался в коде.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Готовим окружение

**Где работаем:** Termux: каталог ~/bot.

**Действие:** В ~/bot выполните `python -m venv .venv`, затем `source .venv/bin/activate` и `python -m pip install vk_api`. При новом сеансе повторяется активация, а не создание среды. Окружение Windows на телефон не копируйте.

**Порядок выполнения и ориентиры:** Перед командами выполните cd ~/bot. Вводите создание среды, source и установку по одной строке. После установки выполните проверку import из задания; source относится к Termux, а не к PowerShell.

**Блок 5.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Создаём среду в каталоге бота и устанавливаем пакет после её активации.

```bash
cd ~/bot
python -m venv .venv
source .venv/bin/activate
python -m pip install vk_api
```

**Что должно получиться:** Проверка импорта вернула приглашение без ошибки. Отсутствие печатного ответа здесь означает успешный импорт.

**Проверка:** команда `python -c "import vk_api"` завершается без ошибки.

- [ ] Получилось; могу объяснить изменение.

### Шаг 6. Запускаем один экземпляр

**Где работаем:** TERMINAL VS Code для остановки на ПК; Termux для запуска на телефоне.

**Действие:** Остановите бота на компьютере через Ctrl+C. На телефоне выполните `termux-wake-lock`, затем `python bot.py`; введите токен в скрытом приглашении. Проверьте кнопки и вопрос. Два процесса одного бота одновременно в учебном проекте не запускаем.

**Порядок выполнения и ориентиры:** В VS Code щёлкните в терминале бота и нажмите Ctrl+C. Затем в Termux выполните wake-lock и запуск. После приглашения ключа вставьте токен и нажмите Enter, даже если символы не видны.

**Блок 6.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Сначала выбираем каталог и среду, затем запускаем файл. Бот на ПК к этому моменту остановлен.

```bash
cd ~/bot
source .venv/bin/activate
termux-wake-lock
python bot.py
```

**Что должно получиться:** Сообщение о запуске видно на телефоне, вопрос в приложении VK получает ответ. На ПК бот остановлен.

**Проверка:** бот отвечает с телефона при остановленном процессе Windows.

- [ ] Получилось; могу объяснить изменение.

### Шаг 7. Останавливаем и повторяем

**Где работаем:** Termux: клавиши Ctrl и C; затем строка команд.

**Действие:** Нажмите Ctrl+C в Termux, выполните `termux-wake-unlock`. Запустите бота повторно и снова остановите. Wake lock уменьшает засыпание процессора, но не обеспечивает работу 24/7: Android, связь и батарея могут прервать процесс. Для постоянной работы нужен отдельный хостинг.

**Порядок выполнения и ориентиры:** Остановите процесс сочетанием Ctrl+C; если клавиши Ctrl нет на экранной клавиатуре, используйте дополнительную клавиатуру Termux. После возврата приглашения выполните wake-unlock. Для повторного опыта активируйте среду, если сеанс был закрыт.

**Блок 7.1 · куда вставить:** В Termux на Android, не в Windows PowerShell. Выполняйте строки по одной, дожидаясь завершения предыдущей.

**Зачем и почему здесь:** Команда выполняется после Ctrl+C, когда Termux снова принимает команды; до остановки ввод попадёт работающей программе.

```bash
termux-wake-unlock
```

**Что должно получиться:** Приглашение вернулось; вы можете заново запустить тот же файл без копирования и установки пакетов.

**Проверка:** вы умеете запускать и останавливать бота без переустановки.

- [ ] Получилось; могу объяснить изменение.

## Домашняя работа · небольшая доработка

Добавьте перед циклом вывод «Магический шар запущен на Android» в телефонной копии. Запишите в памятку команды перехода в каталог, активации, запуска и остановки. Проверьте один повторный запуск по этой памятке. Если работаете на ПК — измените сообщение на «…на компьютере» и выполните ту же проверку.

**Где выполнить и как проверить домашнюю работу:** На ПК редактируйте bot.py в VS Code; телефонную копию после переноса можно открыть nano bot.py в Termux. Сообщение запуска стоит до цикла. После сохранения повторите запуск по собственной памятке: новая надпись видна на устройстве, бот отвечает.
