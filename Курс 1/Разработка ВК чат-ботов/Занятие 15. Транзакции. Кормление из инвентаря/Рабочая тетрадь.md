## Классная работа

### Шаг 1. Находим несогласованность

Теперь «Кормить» должно уменьшать корм на 1 и повышать сытость на 20, максимум 100. Если предмет списали, а UPDATE питомца сломался, игрок потеряет корм. Транзакция сохраняет обе правки вместе либо откатывает обе. При полном насыщении и отсутствии питомца корм не тратится.

**Проверка:** можете описать два действия, которые должны сохраниться вместе.

- [ ] Получилось; могу объяснить изменение.

### Шаг 2. Заменяем старую функцию

Изменяйте существующую feed_pet, а не добавляйте второй обработчик. Функция получает conn и owner_id. Проверьте питомца и насыщение до изменения, верните понятный статус при отказе. Для двух записей используйте `with conn:`. В стандартном режиме sqlite3 этот контекст сохраняет успешную транзакцию и откатывает её при исключении. Он не закрывает соединение: close остаётся в finally всего бота. Не включайте autocommit=True и не выполняйте commit между двумя UPDATE.

**Проверка:** нашли и удалили прежний commit между действиями, если он был.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Списываем с условием

Внутри with выполните UPDATE inventory SET quantity = quantity - 1 WHERE owner_id = ? AND item = ? AND quantity >= 1 с параметрами (owner_id, "корм"). Если rowcount равен 0, верните статус «нет корма»: изменений ещё нет. Строку с quantity = 0 оставьте в таблице, иначе подарок можно получить заново.

**Проверка:** отсутствующий корм и нулевое количество не уходят в минус.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Обновляем питомца в той же транзакции

Сразу после успешного списания выполните UPDATE pets SET satiety = MIN(100, satiety + 20) WHERE owner_id = ? AND satiety < 100. Если rowcount не равен 1, поднимите ValueError с понятным описанием, чтобы with откатил списание. Статус успеха возвращайте после выхода из with. Исключение внутри with не подавляйте: оно должно дойти до менеджера контекста для rollback.

**Проверка:** успех уменьшает корм на 1 и повышает сытость; при ошибке не меняется ни одно значение.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Показываем результат пользователю

В ветке «кормить» используйте статусы новой функции: питомца нет, уже сыт, нет корма, успех. Исключения sqlite3.Error и ValueError перехватите снаружи вызова функции, после выхода из её with; сообщите о неудаче, не показывая пользователю внутренний SQL. Уберите из помощи обещание бесплатного корма. Для этого учебного бота достаточно одного процесса и одного соединения.

**Проверка:** команда имеет одно значение: кормление из рюкзака.

- [ ] Получилось; могу объяснить изменение.

### Шаг 6. Доказываем откат

В учебной копии перед вторым UPDATE временно вызовите `raise ValueError("Учебная ошибка")`. Сытость до опыта должна быть меньше 100, корм — больше 0. Вызовите кормление, затем прочитайте обе таблицы: значения должны остаться прежними. Уберите искусственную ошибку, повторите и проверьте успешную пару изменений.

**Проверка:** проверен и успешный путь, и rollback; учебная ошибка удалена.

- [ ] Получилось; могу объяснить изменение.
