## Как выполнять действия в VS Code

1. Откройте **File → Open Folder / Файл → Открыть папку** и выберите свою папку `vk_bot`. Слева в **Explorer / Проводник** (`Ctrl+Shift+E`) находятся файлы, в центре — редактор выбранного файла. Файлы `.py` создавайте в корне `vk_bot`, не внутри `.venv`.
2. Код Python вводите в центральный редактор файла `.py`, затем нажимайте `Ctrl+S`. Точка на вкладке означает несохранённые изменения. Фрагменты SQL помещайте в кавычках в аргументы `execute` в Python-файле; их не вводят как команды PowerShell.
3. Команды установки и запуска вводите внизу: **Terminal → New Terminal / Терминал → Создать терминал**. В этой тетради для Windows используется **PowerShell**. Щёлкните после приглашения `PS …>`, наберите команду без самого приглашения и нажмите `Enter`. Панели **Output / Вывод** и **Debug Console / Консоль отладки** для этих команд не подходят.
4. Проверьте текущую папку командой `Get-Location`: путь должен оканчиваться на `vk_bot`. Командой `Get-ChildItem` посмотрите файлы: нужный `.py` и папка `.venv` должны быть здесь. Если папка другая, откройте правильную через File → Open Folder и создайте новый терминал. Если видите `>>>`, открыт интерактивный Python: введите `exit()` и Enter, чтобы вернуться к PowerShell.
5. После создания окружения запускайте нужный файл командой из блока ниже. Начальное `.\` означает «из текущей папки». Если PowerShell активировал среду автоматически, прямой путь всё равно подходит. Если `.venv` ещё нет, сначала выполните создание среды из занятия 2.

```powershell
.\.venv\Scripts\python.exe db_lab.py
```

6. Пока бот работает, приглашение `PS …>` не возвращается: терминал занят программой. Вопросы и команды боту отправляйте в **диалоге с сообществом VK**. Консольной программе ответ на `input` вводите в том же TERMINAL после её вопроса. Ключ вводится только после приглашения `Токен сообщества:`; символы `getpass` не отображаются.
7. Перед новой правкой щёлкните в TERMINAL и нажмите `Ctrl+C`, дождитесь приглашения PowerShell. Исправьте файл, сохраните `Ctrl+S`, снова выполните команду запуска. Работающая программа не подхватывает сохранённые изменения сама. Ошибки Python читаем в TERMINAL: последняя строка — тип и описание, выше — файл и номер строки. Кнопка Problems / Проблемы помогает найти синтаксические замечания, но не заменяет запуск.

**Как проверять SQLite:** `pets.db` не открывают как текст и не запускают Python. Состояние проверяется запросами SELECT: в занятии 9 результат печатается в TERMINAL, с занятия 10 — показывается командами «Питомец» и «Инвентарь» в VK. Сначала сохраните программу, затем запустите её; одно появление файла БД не доказывает правильность записей.

## Как копировать учебные блоки

Копируйте **по одному блоку до 10 строк**, а не весь материал занятия. Перед каждым блоком указаны файл, место вставки или замены и причина такого расположения. Несколько блоков одного шага выполняйте по порядку. Если код уже набран по описанию, второй раз его не добавляйте — сравните с образцом.

Сохраняйте начальные пробелы: они показывают вложенность Python. После вставки проверьте выравнивание с названными соседними строками; VS Code может автоматически добавить лишний отступ. Код с меткой `python` идёт в редактор `.py`, `powershell` — в TERMINAL Windows, `bash` — в Termux. Номер шага, пояснение и ограждения из трёх обратных кавычек в файл не переносятся. В блоках нет скрытого продолжения в виде троеточия: если блок открывает try или функцию, явно указано, каким следующим блоком завершить сборку до запуска.

### Шаг 3. Описываем таблицу

**Где работаем:** Редактор db_lab.py: после cur = conn.cursor(), до закрытия соединения.

**Действие:** Вызовите cur.execute с SQL создания таблицы. Составьте запрос: `CREATE TABLE IF NOT EXISTS pets (...)`. В скобках перечислите owner_id INTEGER PRIMARY KEY, name TEXT NOT NULL, satiety INTEGER NOT NULL DEFAULT 50, mood INTEGER NOT NULL DEFAULT 50, xp INTEGER NOT NULL DEFAULT 0. owner_id — ID владельца VK, одна строка на владельца; name — имя; сытость и настроение измеряем от 0 до 100. Вызовите conn.commit(). IF NOT EXISTS позволяет запускать создание повторно, но не изменяет столбцы уже существующей таблицы.

**Порядок выполнения и ориентиры:** SQL поместите строкой в кавычках внутрь вызова cur.execute; перечисление столбцов заменяет троеточие в шаблоне. После execute добавьте commit. SQL не вводится отдельно после PS. Сохраните и запустите файл дважды.

**Блок 3.1 · куда вставить:** В db_lab.py после cur = conn.cursor(). Тройные кавычки охватывают одну SQL-строку.

**Зачем и почему здесь:** Таблица должна существовать до вставки или чтения. Commit завершает подготовку схемы.

```python
cur.execute("""CREATE TABLE IF NOT EXISTS pets (
    owner_id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    satiety INTEGER NOT NULL DEFAULT 50,
    mood INTEGER NOT NULL DEFAULT 50,
    xp INTEGER NOT NULL DEFAULT 0
)""")
conn.commit()
```

**Что должно получиться:** Оба запуска завершаются без ошибки. Само отсутствие ошибки ещё не доказывает данные: их прочитаем на шаге 5.

**Проверка:** повторный запуск не выдаёт «table already exists». Нарисуйте одну строку таблицы с пятью значениями.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Добавляем имя параметром

**Где работаем:** Редактор db_lab.py: после создания таблицы и её commit.

**Действие:** Получите имя через input и strip; пустое имя попросите ввести заново до записи. Для учебного владельца возьмите число 1. Соберите SQL `INSERT OR IGNORE INTO pets (owner_id, name) VALUES (?, ?)`. Передайте его первым аргументом cur.execute, а вторым — кортеж `(1, pet_name)`. Вопросительные знаки обозначают значения, не имена столбцов. Затем вызовите conn.commit(). Здесь OR IGNORE сохраняет прежнего питомца при повторном ID.

**Порядок выполнения и ориентиры:** Сначала добавьте ввод pet_name, затем проверку непустого имени, execute вставки и commit. Пока цикл повторного ввода не знаком, используйте while not pet_name с новым input внутри; он повторяет запрос до непустой строки. При запуске имя вводите в TERMINAL после приглашения программы.

**Блок 4.1 · куда вставить:** После commit создания таблицы. Для опыта со вторым владельцем позже меняйте owner_id только здесь.

**Зачем и почему здесь:** Ввод и проверка идут до INSERT; ? получают отдельные значения и корректно обрабатывают кавычки.

```python
owner_id = 1
pet_name = input("Имя питомца: ").strip()
while not pet_name:
    pet_name = input("Имя не должно быть пустым: ").strip()
cur.execute(
    "INSERT OR IGNORE INTO pets (owner_id, name) VALUES (?, ?)",
    (owner_id, pet_name)
)
conn.commit()
```

**Что должно получиться:** На этом шаге вводится имя, но карточка ещё не выводится. Проверять сохранённую строку будем SELECT на следующем шаге.

**Проверка:** создана одна строка; повторный запуск с ID 1 не меняет её имя.

### Шаг 5. Читаем и закрываем

**Где работаем:** Редактор db_lab.py: SELECT после commit вставки, вывод перед close.

**Действие:** После вставки выполните `SELECT name, satiety FROM pets WHERE owner_id = ?`, передав `(1,)` вторым аргументом execute. Запятая обязательна: это кортеж из одного элемента. Вызовите cur.fetchone(), сохраните в row. Если row is None, записи нет; иначе имя лежит в row[0], сытость — в row[1]. Выведите их. В конце вызовите conn.close(). После успешной первой проверки оберните работу с соединением в try/finally и перенесите close в finally: ресурс закроется и при ошибке.

**Порядок выполнения и ориентиры:** Добавьте запрос, получение row и print для его значений. После проверки перенесите действия от создания курсора до вывода в try с отступом 4 пробела; finally выровняйте с try, close разместите внутри finally. Сам conn создаётся перед try. Сохраните и запустите дважды, вводя разные имена для ID 1.

**Блок 5.1 · куда вставить:** После commit вставки; до закрытия соединения.

**Зачем и почему здесь:** Сначала выполняется запрос, затем читается результат. Проверка None предшествует доступу по индексу.

```python
cur.execute("SELECT name, satiety FROM pets WHERE owner_id = ?", (owner_id,))
row = cur.fetchone()
if row is None:
    print("Питомец не найден")
else:
    print("Имя:", row[0], "Сытость:", row[1])
```

**Блок 5.2 · куда вставить:** Сначала добавьте закрытие в конец db_lab.py и проверьте запуск. Затем перенесите его под finally по инструкции ниже; второй close не оставляйте.

**Зачем и почему здесь:** Соединение закрывается после последнего чтения, иначе SELECT уже не сможет работать.

```python
conn.close()
```

**Блок 5.3 · куда вставить:** Для защиты при ошибке: после conn = sqlite3.connect(db_path) вставьте строку try. Все строки ниже от cur до вывода сдвиньте на 4 пробела; прежний close удалите. Затем добавьте блок finally из следующего фрагмента.

**Зачем и почему здесь:** Try начинает область работы с открытым соединением. Пока finally не добавлен, файл синтаксически не завершён — не запускайте промежуточный вариант.

```python
try:
```

**Блок 5.4 · куда вставить:** В конец файла, выровняв finally с try без отступа; close внутри имеет 4 пробела.

**Зачем и почему здесь:** Finally исполняется и при исключении. Он должен завершать весь участок работы с БД, а не только INSERT.

```python
finally:
    conn.close()
```

**Что должно получиться:** На втором запуске напечатано первое сохранённое имя и сытость 50. Это проверка INSERT OR IGNORE и сохранения на диске.

**Проверка:** после полного завершения и повторного запуска вы видите сохранённое имя.
