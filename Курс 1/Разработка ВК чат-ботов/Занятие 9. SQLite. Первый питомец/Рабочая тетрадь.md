## Классная работа

### Шаг 1. Отличаем память от файла

Запишите имя в переменную и завершите программу. Переменная исчезла. SQLite хранит таблицы в файле на диске: отдельный сервер не нужен. Используем стандартный модуль sqlite3 и обычные SQL-запросы; ORM и установка пакета sqlite3 через pip не нужны. Проверьте `.venv\Scripts\python.exe -c "import sqlite3; print(sqlite3.sqlite_version)"`.

### Шаг 2. Задаём постоянный путь

В начало db_lab.py добавьте import sqlite3 и импорт Path из pathlib. После импортов задайте `db_path = Path(__file__).resolve().with_name("pets.db")`. Затем создайте соединение conn через `sqlite3.connect(db_path)`, а cur — через `conn.cursor()`. Файл расположен рядом со скриптом, независимо от папки запуска. Пока соединение не закрыли, используйте его для следующих шагов.

### Шаг 3. Описываем таблицу

Вызовите cur.execute с SQL создания таблицы. Составьте запрос: `CREATE TABLE IF NOT EXISTS pets (...)`. В скобках перечислите owner_id INTEGER PRIMARY KEY, name TEXT NOT NULL, satiety INTEGER NOT NULL DEFAULT 50, mood INTEGER NOT NULL DEFAULT 50, xp INTEGER NOT NULL DEFAULT 0. owner_id — ID владельца VK, одна строка на владельца; name — имя; сытость и настроение измеряем от 0 до 100. Вызовите conn.commit(). IF NOT EXISTS позволяет запускать создание повторно, но не изменяет столбцы уже существующей таблицы.

**Проверка:** повторный запуск не выдаёт «table already exists». Нарисуйте одну строку таблицы с пятью значениями.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Добавляем имя параметром

Получите имя через input и strip; пустое имя попросите ввести заново до записи. Для учебного владельца возьмите число 1. Соберите SQL `INSERT OR IGNORE INTO pets (owner_id, name) VALUES (?, ?)`. Передайте его первым аргументом cur.execute, а вторым — кортеж `(1, pet_name)`. Вопросительные знаки обозначают значения, не имена столбцов. Затем вызовите conn.commit(). Здесь OR IGNORE сохраняет прежнего питомца при повторном ID.

**Проверка:** создана одна строка; повторный запуск с ID 1 не меняет её имя.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Читаем и закрываем

После вставки выполните `SELECT name, satiety FROM pets WHERE owner_id = ?`, передав `(1,)` вторым аргументом execute. Запятая обязательна: это кортеж из одного элемента. Вызовите cur.fetchone(), сохраните в row. Если row is None, записи нет; иначе имя лежит в row[0], сытость — в row[1]. Выведите их. В конце вызовите conn.close(). После успешной первой проверки оберните работу с соединением в try/finally и перенесите close в finally: ресурс закроется и при ошибке.

**Проверка:** после полного завершения и повторного запуска вы видите сохранённое имя.

- [ ] Получилось; могу объяснить изменение.

### Шаг 6. Проверяем текст с кавычкой

Сначала попробуйте имя с апострофом для другого учебного ID. Передавайте его только отдельным параметром execute. Не подставляйте ввод f-строкой в SQL: кавычки могут сломать запрос и изменить его смысл. Для чтения другого владельца замените параметр ID, а не текст запроса.

**Проверка:** имя с кавычкой читается без ошибки; строки двух владельцев различаются.
