## Классная работа

### Шаг 1. Договариваемся о правилах

Команда «Играть» тратит 10 сытости, добавляет 15 настроения (не больше 100) и 5 опыта. Разрешаем игру при сытости не ниже 10. Опыт пока только растёт. Никаких таймеров и уменьшения состояния по часам в этом уроке нет.

**Проверка:** для сытости 10 игра разрешена, для 9 — нет.

- [ ] Получилось; могу объяснить изменение.

### Шаг 2. Обновляем одной операцией

До подключения добавьте play_pet(conn, owner_id). В SQL UPDATE перечислите через запятую satiety = satiety - 10, mood = MIN(100, mood + 15), xp = xp + 5. В WHERE укажите owner_id = ? AND satiety >= 10. Выполните, сохраните через commit и верните rowcount. Все три изменения относятся к одному успешному действию.

**Проверка:** успешная игра меняет три поля; неуспешная не добавляет опыт.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Обрабатываем результат

В ветке «играть» сначала проверьте наличие через get_pet. Затем вызовите play_pet и по rowcount сформируйте ответ: успех или просьба покормить. Для успеха перечитайте строку и покажите новые показатели. Добавьте кнопку и помощь.

**Проверка:** повторные игры останавливаются при недостатке сытости.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Вычисляем уровень

В карточке после чтения вычислите level как `1 + pet[4] // 20`, где pet — возвращённый get_pet кортеж. // — целочисленное деление. Уровень не храним отдельным столбцом: он вычисляется из опыта. Добавьте его в f-строку карточки.

**Проверка:** при опыте 0 уровень 1, при 20 — 2, при 40 — 3.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Проверяем границы

Для тестов используйте отдельную копию БД или учебный профиль. Проверьте сытость 0, 9, 10; настроение 95; опыт 15. На состоянии 10/95/15 после игры ожидаем 0/100/20 и уровень 2. Не меняйте показатели других пользователей ради тестов.

**Проверка:** все граничные случаи совпали с правилами.

- [ ] Получилось; могу объяснить изменение.
