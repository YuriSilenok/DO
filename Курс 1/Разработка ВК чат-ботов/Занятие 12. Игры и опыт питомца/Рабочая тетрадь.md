## Как выполнять действия в VS Code

1. Откройте **File → Open Folder / Файл → Открыть папку** и выберите свою папку `vk_bot`. Слева в **Explorer / Проводник** (`Ctrl+Shift+E`) находятся файлы, в центре — редактор выбранного файла. Файлы `.py` создавайте в корне `vk_bot`, не внутри `.venv`.
2. Код Python вводите в центральный редактор файла `.py`, затем нажимайте `Ctrl+S`. Точка на вкладке означает несохранённые изменения. Фрагменты SQL помещайте в кавычках в аргументы `execute` в Python-файле; их не вводят как команды PowerShell.
3. Команды установки и запуска вводите внизу: **Terminal → New Terminal / Терминал → Создать терминал**. В этой тетради для Windows используется **PowerShell**. Щёлкните после приглашения `PS …>`, наберите команду без самого приглашения и нажмите `Enter`. Панели **Output / Вывод** и **Debug Console / Консоль отладки** для этих команд не подходят.
4. Проверьте текущую папку командой `Get-Location`: путь должен оканчиваться на `vk_bot`. Командой `Get-ChildItem` посмотрите файлы: нужный `.py` и папка `.venv` должны быть здесь. Если папка другая, откройте правильную через File → Open Folder и создайте новый терминал. Если видите `>>>`, открыт интерактивный Python: введите `exit()` и Enter, чтобы вернуться к PowerShell.
5. После создания окружения запускайте нужный файл командой из блока ниже. Начальное `.\` означает «из текущей папки». Если PowerShell активировал среду автоматически, прямой путь всё равно подходит. Если `.venv` ещё нет, сначала выполните создание среды из занятия 2.

```powershell
.\.venv\Scripts\python.exe pet_bot.py
```

6. Пока бот работает, приглашение `PS …>` не возвращается: терминал занят программой. Вопросы и команды боту отправляйте в **диалоге с сообществом VK**. Консольной программе ответ на `input` вводите в том же TERMINAL после её вопроса. Ключ вводится только после приглашения `Токен сообщества:`; символы `getpass` не отображаются.
7. Перед новой правкой щёлкните в TERMINAL и нажмите `Ctrl+C`, дождитесь приглашения PowerShell. Исправьте файл, сохраните `Ctrl+S`, снова выполните команду запуска. Работающая программа не подхватывает сохранённые изменения сама. Ошибки Python читаем в TERMINAL: последняя строка — тип и описание, выше — файл и номер строки. Кнопка Problems / Проблемы помогает найти синтаксические замечания, но не заменяет запуск.

**Как проверять SQLite:** `pets.db` не открывают как текст и не запускают Python. Состояние проверяется запросами SELECT: в занятии 9 результат печатается в TERMINAL, с занятия 10 — показывается командами «Питомец» и «Инвентарь» в VK. Сначала сохраните программу, затем запустите её; одно появление файла БД не доказывает правильность записей.

## Классная работа

### Шаг 1. Договариваемся о правилах

**Где работаем:** VS Code → checks.md: правила новой команды.

**Действие:** Команда «Играть» тратит 10 сытости, добавляет 15 настроения (не больше 100) и 5 опыта. Разрешаем игру при сытости не ниже 10. Опыт пока только растёт. Никаких таймеров и уменьшения состояния по часам в этом уроке нет.

**Порядок выполнения и ориентиры:** Запишите стоимость игры и награду до изменения pet_bot.py. Рядом выпишите два случая: сытость 9 и 10.

**Что должно получиться:** Для 9 нет изменений; для 10 ожидается 0 сытости и прибавка опыта.

**Проверка:** для сытости 10 игра разрешена, для 9 — нет.

### Шаг 2. Обновляем одной операцией

**Где работаем:** Редактор pet_bot.py: play_pet рядом с feed_pet, над подключением.

**Действие:** До подключения добавьте play_pet(conn, owner_id). В SQL UPDATE перечислите через запятую satiety = satiety - 10, mood = MIN(100, mood + 15), xp = xp + 5. В WHERE укажите owner_id = ? AND satiety >= 10. Выполните, сохраните через commit и верните rowcount. Все три изменения относятся к одному успешному действию.

**Порядок выполнения и ориентиры:** Добавьте функцию с курсором и одним UPDATE, затем commit и возврат rowcount. Три изменения разделяются запятыми внутри SQL, а не отдельными вызовами commit.

**Что должно получиться:** После команды следующего шага меняются одновременно сытость, настроение и опыт; нет начисления опыта при отказе.

**Проверка:** успешная игра меняет три поля; неуспешная не добавляет опыт.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Обрабатываем результат

**Где работаем:** Редактор pet_bot.py: ветка «играть», блок кнопок и помощь.

**Действие:** В ветке «играть» сначала проверьте наличие через get_pet. Затем вызовите play_pet и по rowcount сформируйте ответ: успех или просьба покормить. Для успеха перечитайте строку и покажите новые показатели. Добавьте кнопку и помощь.

**Порядок выполнения и ориентиры:** Добавьте обработчик до else, кнопку — перед циклом. В ответе успеха используйте новую строку get_pet после UPDATE. Сохраните и перезапустите файл в TERMINAL.

**Что должно получиться:** Отправьте «Играть», затем «Питомец»: при начальных 50/50/0 увидите 40/65/5.

**Проверка:** повторные игры останавливаются при недостатке сытости.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Вычисляем уровень

**Где работаем:** Редактор pet_bot.py: только сборка карточки в ветке «питомец».

**Действие:** В карточке после чтения вычислите level как `1 + pet[4] // 20`, где pet — возвращённый get_pet кортеж. // — целочисленное деление. Уровень не храним отдельным столбцом: он вычисляется из опыта. Добавьте его в f-строку карточки.

**Порядок выполнения и ориентиры:** После проверки наличия pet и перед присваиванием reply вычислите level. Используйте ту же переменную pet, что хранит строку SELECT. Добавьте level в текст карточки.

**Что должно получиться:** После четырёх успешных игр от нулевого опыта карточка показывает опыт 20 и уровень 2.

**Проверка:** при опыте 0 уровень 1, при 20 — 2, при 40 — 3.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Проверяем границы

**Где работаем:** Отдельная учебная копия проекта в VS Code, не чужой профиль.

**Действие:** Для тестов используйте отдельную копию БД или учебный профиль. Проверьте сытость 0, 9, 10; настроение 95; опыт 15. На состоянии 10/95/15 после игры ожидаем 0/100/20 и уровень 2. Не меняйте показатели других пользователей ради тестов.

**Порядок выполнения и ориентиры:** Остановите бота. В файловом менеджере скопируйте pet_bot.py и pets.db в папку pet_test, откройте её отдельным окном VS Code. Для точного состояния создайте там prepare_test.py: подключитесь к pets.db по __file__, выполните UPDATE только учебного owner_id с параметрами 10, 95, 15 и commit/close. Запустите этот файл в TERMINAL, затем копию бота и одну игру. Для 0 и 9 повторите подготовку, меняя только сытость.

**Что должно получиться:** При 10/95/15 получается 0/100/20; при 0 и 9 игра отказывается и опыт прежний. После опыта остановите копию и вернитесь к основному проекту.

**Как подготовить окно проверки:** после остановки бота откройте папку проекта в Проводнике Windows и создайте рядом папку `pet_test`. Скопируйте в неё только `pet_bot.py` и `pets.db`. В VS Code выберите File → New Window, затем File → Open Folder → `pet_test`. В новом окне откройте Terminal → New Terminal и выполните по очереди `py -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install vk_api`. Папка тестов имеет собственное окружение; исходный проект остаётся в прежнем окне.

**Как проверить подготовку значений:** в Explorer нового окна создайте `prepare_test.py`. В нём используйте знакомые шаги занятия 9: импорты, путь к `pets.db` через `__file__`, подключение, курсор. В `execute` передайте строку `UPDATE pets SET satiety = ?, mood = ?, xp = ? WHERE owner_id = ?` и кортеж `(10, 95, 15, ваш_числовой_ID)`. Вместо последнего обозначения впишите число владельца учебного питомца; его можно узнать командой «Мой номер» в сохранённом «Магическом шаре», остановив другие процессы на время запроса. После запроса выполните `commit` и `close`. Сохраните и запустите в TERMINAL командой `.\.venv\Scripts\python.exe prepare_test.py`. Затем запустите `.\.venv\Scripts\python.exe pet_bot.py` и запросите карточку: **до игры** она должна показывать 10/95/15. Если карточка другая, проверьте ID и папку БД, а не продолжайте проверку на неверном состоянии.

**Проверка:** все граничные случаи совпали с правилами.
