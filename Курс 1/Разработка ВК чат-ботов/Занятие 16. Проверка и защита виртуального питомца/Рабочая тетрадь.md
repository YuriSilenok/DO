## Классная работа

### Шаг 1. Составляем приёмочные сценарии

Подготовьте таблицу: нет питомца → приютить → повторно приютить → переименовать → подарок дважды → играть → кормить → инвентарь → перезапуск. Для каждого пункта запишите ожидаемые изменения pets и inventory. Отдельно проверьте сытость 100, нулевой корм и чужой профиль.

**Проверка:** в каждом случае понятно, какие строки должны измениться и какие остаться прежними.

- [ ] Получилось; могу объяснить изменение.

### Шаг 2. Повторяем проверку сохранения

Выполните сценарии, остановите процесс через Ctrl+C и запустите заново. Имя, опыт, сытость, настроение и инвентарь должны сохраниться. Убедитесь, что запущен именно файл с нужным pets.db. Если файл оказался в другой папке, проверьте путь на основе __file__.

**Проверка:** после перезапуска показатели совпадают с записанными.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Делаем резервную копию

Для простого учебного способа полностью остановите бота и убедитесь, что соединение закрыто. Скопируйте pets.db в pets-backup.db средствами файлового менеджера. Если около базы остаются файлы -wal/-shm или процесс нельзя остановить, не копируйте один файл наугад: используйте Connection.backup из документации вместе с преподавателем. Рабочую базу не выкладывайте в общий репозиторий.

**Проверка:** копия создана после штатной остановки, исходник сохранён.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Проверяем восстановление отдельно

Создайте отдельную папку проверки, скопируйте туда pet_bot.py и резервную копию, назовите её pets.db. Запускайте копию только при остановленном основном боте. Окружение используйте существующее, вызывая Python по полному пути, или создайте новое по занятию 2. Прочитайте профиль и инвентарь. Не заменяйте основную базу ради опыта.

**Проверка:** проверочная копия содержит ожидаемые показатели; основной файл не потерян.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Готовим защиту

За 3 минуты покажите приют, имя, карточку и инвентарь. На одном слайде нарисуйте две таблицы и связь по owner_id; на другом — путь сообщения до SQL и ответа. Объясните ?, WHERE, commit, fetchone/fetchall и rollback. Продемонстрируйте сохранение после перезапуска.

**Проверка:** можете объяснить каждое изменение без чтения готового исходника.

- [ ] Получилось; могу объяснить изменение.

Запишите: это учебный бот с одним процессом, ручным запуском и небольшим числом игроков; в нём нет автоматического старения и бесконечной выдачи корма. После стартового подарка корм конечен — это правило текущей версии. Составьте план следующей функции, например ежедневного подарка с датой в БД, но не обещайте её как уже работающую.
