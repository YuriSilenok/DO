## Как выполнять действия в VS Code

1. Откройте **File → Open Folder / Файл → Открыть папку** и выберите свою папку `vk_bot`. Слева в **Explorer / Проводник** (`Ctrl+Shift+E`) находятся файлы, в центре — редактор выбранного файла. Файлы `.py` создавайте в корне `vk_bot`, не внутри `.venv`.
2. Код Python вводите в центральный редактор файла `.py`, затем нажимайте `Ctrl+S`. Точка на вкладке означает несохранённые изменения. Фрагменты SQL помещайте в кавычках в аргументы `execute` в Python-файле; их не вводят как команды PowerShell.
3. Команды установки и запуска вводите внизу: **Terminal → New Terminal / Терминал → Создать терминал**. В этой тетради для Windows используется **PowerShell**. Щёлкните после приглашения `PS …>`, наберите команду без самого приглашения и нажмите `Enter`. Панели **Output / Вывод** и **Debug Console / Консоль отладки** для этих команд не подходят.
4. Проверьте текущую папку командой `Get-Location`: путь должен оканчиваться на `vk_bot`. Командой `Get-ChildItem` посмотрите файлы: нужный `.py` и папка `.venv` должны быть здесь. Если папка другая, откройте правильную через File → Open Folder и создайте новый терминал. Если видите `>>>`, открыт интерактивный Python: введите `exit()` и Enter, чтобы вернуться к PowerShell.
5. После создания окружения запускайте нужный файл командой из блока ниже. Начальное `.\` означает «из текущей папки». Если PowerShell активировал среду автоматически, прямой путь всё равно подходит. Если `.venv` ещё нет, сначала выполните создание среды из занятия 2.

```powershell
.\.venv\Scripts\python.exe pet_bot.py
```

6. Пока бот работает, приглашение `PS …>` не возвращается: терминал занят программой. Вопросы и команды боту отправляйте в **диалоге с сообществом VK**. Консольной программе ответ на `input` вводите в том же TERMINAL после её вопроса. Ключ вводится только после приглашения `Токен сообщества:`; символы `getpass` не отображаются.
7. Перед новой правкой щёлкните в TERMINAL и нажмите `Ctrl+C`, дождитесь приглашения PowerShell. Исправьте файл, сохраните `Ctrl+S`, снова выполните команду запуска. Работающая программа не подхватывает сохранённые изменения сама. Ошибки Python читаем в TERMINAL: последняя строка — тип и описание, выше — файл и номер строки. Кнопка Problems / Проблемы помогает найти синтаксические замечания, но не заменяет запуск.

**Как проверять SQLite:** `pets.db` не открывают как текст и не запускают Python. Состояние проверяется запросами SELECT: в занятии 9 результат печатается в TERMINAL, с занятия 10 — показывается командами «Питомец» и «Инвентарь» в VK. Сначала сохраните программу, затем запустите её; одно появление файла БД не доказывает правильность записей.

**Где работаем:** VS Code → Explorer: копия bot.py с именем pet_bot.py.

**Действие:** В pet_bot.py измените приветствие и помощь: это виртуальный питомец. Удалите ветки предсказаний и кнопки шара, добавьте кнопки «Питомец» и «Приютить». Уберите неиспользуемые answers и random. Сохраните получение событий, фильтр личного диалога, getpass и единую отправку ответа.

**Порядок выполнения и ориентиры:** Нажмите на bot.py правой кнопкой, Copy, затем Paste в той же папке и переименуйте копию клавишей F2. Откройте именно pet_bot.py. В ней замените тексты и ветки шара; оригинальный bot.py не меняйте. Запуск новой копии: `.\.venv\Scripts\python.exe pet_bot.py` в TERMINAL.

**Что должно получиться:** В заголовке вкладки pet_bot.py. «Помощь» в VK описывает питомца, а не предсказания. Старый процесс bot.py остановлен.

**Проверка:** сообщения VK доходят; прежние команды шара не выдают случайных предсказаний.

### Шаг 2. Открываем БД один раз

**Где работаем:** Редактор pet_bot.py: БД перед циклом, try/finally вокруг слушателя.

**Действие:** Подключите sqlite3 и Path, перенесите путь pets.db рядом с pet_bot.py. Перед циклом подключите conn, создайте таблицу pets с теми же пятью полями, что на занятии 9, и сохраните создание через commit. Не открывайте соединение для каждого сообщения. Сам цикл поместите в try, а conn.close() — в finally после цикла. Если использовали консольную БД с учебными ID, это не реальные профили VK; не выводите их другим пользователям.

**Порядок выполнения и ориентиры:** Импорты SQLite добавьте наверх, путь и conn — после подготовки VK, до цикла. После создания таблицы сделайте commit. Перед for event добавьте try, весь прежний цикл сдвиньте на один отступ: выделение строк и Tab. Finally и close добавьте после цикла; Shift+Tab уменьшает отступ.

**Что должно получиться:** После запуска и Ctrl+C терминал возвращает PS без сообщения об использовании закрытой БД. Соединение не закрывается внутри каждой команды.

**Проверка:** соединение создаётся до listen и закрывается при Ctrl+C.

- [ ] Получилось; могу объяснить изменение.

### Шаг 3. Выносим чтение в функцию

**Где работаем:** Редактор pet_bot.py: определения функций после импортов, до token и подключения.

**Действие:** Между импортами и кодом подключения определите `def get_pet(conn, owner_id):`. В теле создайте локальный курсор, выполните SELECT owner_id, name, satiety, mood, xp FROM pets WHERE owner_id = ? с кортежем параметра и верните fetchone через return. Функция принимает соединение и ID, ничего не печатает и не отправляет в VK. def только описывает действие, вызов выполняет его.

**Порядок выполнения и ориентиры:** Создайте get_pet на нулевом отступе; курсор, SELECT и return внутри функции имеют 4 пробела. Это отдельный блок над основным кодом. После редактирования сохраните и перезапустите бота; вызов появится в командах следующих шагов.

**Что должно получиться:** Само определение ничего не печатает. Вызовы get_pet далее должны возвращать row или None, а не отправлять ответ в VK.

**Проверка:** get_pet(conn, отсутствующий_ID) возвращает None; порядок полей всегда одинаков.

- [ ] Получилось; могу объяснить изменение.

### Шаг 4. Приютили один раз

**Где работаем:** Редактор pet_bot.py: ветка «приютить» внутри MESSAGE_NEW.

**Действие:** В ветке «приютить» выполните INSERT OR IGNORE только с owner_id и name: ID берите из user_id входящего события, имя пока «Искра». Затем commit. По cur.rowcount различите новую строку (1) и уже существующую (0). Существующего питомца не заменяйте. reply сообщает результат.

**Порядок выполнения и ориентиры:** На месте старых веток шара добавьте elif или первый if для команды. Курсор создавайте в этой ветке, значение user_id берите из события. После execute запомните rowcount до других запросов и выполните commit. По результату задайте reply.

**Что должно получиться:** После перезапуска дважды отправьте «Приютить»: сначала подтверждение создания, затем сообщение о существующем питомце.

**Проверка:** повторная команда не сбрасывает питомца.

- [ ] Получилось; могу объяснить изменение.

### Шаг 5. Показываем карточку

**Где работаем:** Редактор pet_bot.py: ветка «питомец» той же цепочки.

**Действие:** В ветке «питомец» вызовите get_pet(conn, user_id). Если None — предложите «Приютить». Иначе соберите reply из name, satiety, mood и xp с помощью f-строки. Индексы кортежа: 0 — owner_id, 1 — name, 2 — satiety, 3 — mood, 4 — xp. Остальные неизвестные сообщения направляйте в помощь.

**Порядок выполнения и ориентиры:** Сохраните результат get_pet в pet. Проверку pet is None разместите внутри ветки, а сборку карточки — в её else. Отправка messages.send остаётся после общей цепочки команд.

**Что должно получиться:** В VK «Питомец» показывает Искру и 50/50/0. Для пользователя без записи — приглашение приютить, без TypeError от обращения к None.

**Проверка:** у нового пользователя есть понятная подсказка; у владельца — карточка.
