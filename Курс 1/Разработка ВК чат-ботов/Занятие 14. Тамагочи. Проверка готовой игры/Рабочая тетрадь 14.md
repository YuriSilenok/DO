## Рабочее место и порядок действий

Откройте **VS Code → File → Open Folder / Файл → Открыть папку → vk_bot**. Слева в **Explorer** (`Ctrl+Shift+E`) открывайте и создавайте файлы; код вставляйте в центральную вкладку `.py`. Файлы проекта находятся рядом с `.venv`, а не внутри неё. Сохраняйте через `Ctrl+S`.

Команды вводятся внизу, **Terminal → New Terminal / Терминал → Создать терминал**, профиль **PowerShell**. Введите `Get-Location` и нажмите Enter: должна быть открыта папка `vk_bot`. Если путь другой, откройте нужную папку и создайте новый терминал. `PS …>` — приглашение оболочки, его копировать не нужно; `>>>` — интерактивный Python, выйдите из него через `exit()` и Enter. Не используйте для запуска панели Output или Debug Console.

Используем окружение занятий 02–04. Если его нет: в TERMINAL выполните `py -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install vk_api`. `sqlite3`, `pathlib` и `time` входят в стандартную библиотеку, отдельно через pip их не устанавливают.

Копируйте **один блок до 10 строк за раз**. Перед блоком указано точное место, причина и замена. Сохраняйте начальные пробелы; если VS Code добавил лишний отступ, выделите вставленные строки и уменьшите его через Shift+Tab. Не добавляйте блок повторно, если уже сделали действие по описанию. Если функция собирается несколькими блоками, запустите проверку только после указанного завершения.

Вопросы и игровые команды отправляйте **в личном диалоге сообщества VK**, а не в PowerShell. В TERMINAL вводятся только команды запуска и секрет после приглашения `Токен сообщества:`. Символы getpass не отображаются. Перед правкой работающего бота нажмите `Ctrl+C` в его терминале, дождитесь `PS`, сохраните файл и запустите заново. Новые изменения не подхватываются работающей программой автоматически.

Ошибки читайте в TERMINAL: последняя строка содержит тип и описание, выше указаны файл и номер строки. Копию полного исходника в тетради не ищем: собираем проект по этапам и проверяем каждую часть.

### Шаг 2. Проверяем правила без VK

**Где работаем:** VS Code → db_check.py, бот остановлен.

Теперь используем проверочный файл как испытание завершённого модуля БД. Сначала замените весь прежний текст db_check.py началом ниже и сразу добавьте продолжение следующего блока. Это отдельный файл проверки, не готовый бот. Все проверки используют учебный ID 1.

**Куда вставить:** Замените прежний db_check.py этим началом; до finally следующего блока не запускайте.

**Зачем и почему здесь:** Проверка открывает БД через тот же модуль. Управляем временем явно, а не ждём урок у таймера.

```python
from pet_db import open_db, get_pet, adopt_pet, refresh_pet, TICK_SECONDS

conn = open_db()
try:
    adopt_pet(conn, 1)
    with conn:
        conn.execute("UPDATE pets SET satiety=70, mood=70, energy=70, updated_at=? "
                     "WHERE owner_id=?", (1000, 1))
```

**Куда вставить:** Продолжите после conn.execute внутри try: pet и assert имеют 4 пробела, finally — без отступа.

**Зачем и почему здесь:** На границе одного периода списание проходит один раз. Повтор в ту же секунду обязан оставить показатели прежними.

```python
    pet = refresh_pet(conn, 1, now=1000 + TICK_SECONDS)
    assert (pet["satiety"], pet["mood"], pet["energy"]) == (65, 67, 68)
    again = refresh_pet(conn, 1, now=1000 + TICK_SECONDS)
    assert again["satiety"] == 65
    print("Проверки времени пройдены")
finally:
    conn.close()
```

**Куда вставить:** В TERMINAL VS Code, после Ctrl+S в db_check.py.

**Зачем и почему здесь:** Отдельный запуск гарантирует, что проверяется сохранённый файл, а не фрагмент в интерактивном Python.

```powershell
.\.venv\Scripts\python.exe db_check.py
```

**Что наблюдать и как проверить:** Ожидается «Проверки времени пройдены» и возврат PS. AssertionError означает несовпадение; по строке определите ожидаемую границу. Учебная запись с датой 1000 потом пересчитается в нули — это не влияет на реальные ID VK.

### Шаг 3. Проверяем отказы и восстановление

**Где работаем:** VK, TERMINAL и pet_checks.md.

Проверьте: полная сытость, полная энергия, недостаток для игры, неверное имя, сообщение без текста, неизвестная команда. Отказ не должен портить состояние, а следующее сообщение обрабатывается. Сохраните карточку, остановите бот на несколько секунд и повторите запуск с тестовым TICK_SECONDS = 2. Потребности должны уменьшиться за простой. Верните 600 и снова перезапустите.

**Что наблюдать и как проверить:** Нулевые показатели не удаляют питомца: можно покормить, отдохнуть и поиграть. Одно сообщение даёт один ответ; процесс продолжает работать после неверного ввода.

- [ ] Получилось; могу объяснить место и назначение правки.

### Шаг 4. Сохраняем резервную копию

**Где работаем:** TERMINAL для остановки, Проводник Windows для копирования.

Остановите бот Ctrl+C, дождитесь PS: finally закрыл соединение. Правой кнопкой по pet_bot.py в Explorer VS Code → Reveal in File Explorer. Скопируйте tamagotchi.db в tamagotchi-backup.db. Затем создайте папку pet_restore, скопируйте туда pet_db.py, pet_bot.py и резервную копию с именем tamagotchi.db. Откройте pet_restore в новом окне VS Code. Создайте там окружение и установите vk_api как на занятии 02/04. Запустите копию только при остановленном основном боте.

**Что наблюдать и как проверить:** Карточка из восстановленной копии читается; по времени она может уменьшиться — это ожидаемо. Основная база не заменена. Если бот нельзя остановить или остаются активные -wal/-shm, используйте sqlite3.Connection.backup по документации вместо копирования одного файла.
